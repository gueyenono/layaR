# layaR

An R package that runs Laya System 1 decision models locally: typed
choice, score and yes/no questions with calibrated probabilities. R
talks to the `laya-onnx` Rust crate through extendr, and `laya-onnx`
runs the models with ONNX Runtime (ORT). No Python is needed at
prediction time.

- Repo: <https://github.com/gueyenono/layaR> (public). Site:
  <https://gueyenono.github.io/layaR/>
- Upstream: <https://github.com/NandhaKishorM/laya> (the `laya-rust/`
  folder is `laya-onnx`).
- Design history, decisions and roadmap: `plan/layaR.md` (long; read the
  section you need). Upstream asks and their status:
  `plan/upstream-issues.md`.
- Notes about the maintainer’s own machine (paths, Nix setup) are in
  `CLAUDE.local.md`, which is not committed.

## Layout

- `R/`: the user API. The main files:
  - `engine.R`: engines, the default engine, `connect()`.
  - `predict.R`, `questions.R`, `presets.R`, `results.R`, `annotate.R`
    (data frames), `text.R`.
  - `models.R`: model root, Hugging Face download,
    [`laya_import_model()`](https://gueyenono.github.io/layaR/reference/laya_import_model.md).
  - `runtime.R`: ORT lookup, download and load.
  - `json.R`: all R↔︎JSON conversion. Always use `to_json()`, with
    `digits = NA`.
  - `conditions.R`: `laya_abort()` and the error kinds.
- `R/extendr-wrappers.R`: **generated**. Every build regenerates it (the
  `document` binary in `src/rust/document.rs`). Never edit it by hand.
- `src/rust/`: the bridge crate `laya_r`. It is thin: JSON in, JSON out,
  no inference logic.
  - Every `rs_*` function returns an envelope (`envelope.rs`). R unwraps
    it with `rs_unwrap()` and raises `laya_error_<kind>` conditions.
  - `runtime.rs` loads ORT.
  - `questions.rs` and `results.rs` translate the Python formats.
- `src/Makevars.in` and `tools/config.R`: from rextendr’s templates.
  `configure` runs `tools/config.R`.
- `tests/testthat/`: model-free tests run everywhere; model-backed tests
  skip without a model.
  - `helper-runtime.R` provides `skip_without_runtime()`.
  - `fixtures/parity/{multilingual,english,typed-decisions}.json` are
    generated by `data-raw/make_fixtures.R`.
- `vignettes/*.Rmd` are **precomputed**: edit the `.Rmd.orig` files,
  then knit them (see “Docs”).
- `laya-repo/`: a local clone of upstream laya
  (<https://github.com/NandhaKishorM/laya>), ignored by git and by
  `R CMD build`. Its golden tests (`laya-rust/tests/golden/`) are the
  fixture source; clone it there to regenerate fixtures. The current
  fixtures came from commit `80a1da1` (0.4.34), older than the pinned
  v0.5.1, which made no API changes.
- `data-raw/`: dev scripts.
  - `make_fixtures.R`: builds the parity and text fixtures.
  - `knit_vignettes.R`: knits the vignettes.
  - `parity_sweep.R`: an old manual parity script.

## Build and test

- Since 0.2.0, building needs only Rust (rustc \>= 1.88): no OpenSSL and
  no network beyond fetching crates.
- Install: `R CMD INSTALL .`. The release build with LTO takes a few
  minutes; `src/rust/target` is git-ignored and can grow to several GB.
- Docs and NAMESPACE: `Rscript -e 'devtools::document()'`.
- Tests: `Rscript -e 'devtools::test()'`. With a model installed, set
  `NOT_CRAN=true` so parity runs.
  - `LAYAR_PARITY=all` runs all 117 parity cases per checkpoint (about 6
    minutes each).
  - `LAYAR_TEST_RUNTIME=true` makes the tests download ORT when it’s
    missing, and fail rather than skip if it won’t load.
- By default models live in
  `tools::R_user_dir("layaR","cache")/onnx/<checkpoint>` (see
  [`laya_model_root()`](https://gueyenono.github.io/layaR/reference/laya_model_root.md))
  and ORT in `tools::R_user_dir("layaR","data")/onnxruntime/<version>/`.
- `test-bridge.R`’s `model_dir()` hard-codes
  `R_user_dir("layaR","cache")/onnx/multilingual`. It ignores
  `layaR.model_root`.
- Check: `Rscript -e 'devtools::check()'`. Site:
  [`pkgdown::check_pkgdown()`](https://pkgdown.r-lib.org/reference/check_pkgdown.html)
  and
  [`pkgdown::build_site()`](https://pkgdown.r-lib.org/reference/build_site.html).

## ONNX Runtime (R/runtime.R, src/rust/src/runtime.rs)

- **Lookup order:**
  1.  `options(layaR.onnxruntime = path)`.
  2.  The `ORT_DYLIB_PATH` environment variable.
  3.  layaR’s own install:
      `tools::R_user_dir("layaR","data")/onnxruntime/1.28.0/<lib>`.
- **Download:**
  [`laya_install_runtime()`](https://gueyenono.github.io/layaR/reference/laya_install_runtime.md)
  downloads the NuGet package `Microsoft.ML.OnnxRuntime` 1.28.0 (139
  MB), checks the SHA-512 that NuGet publishes, and extracts this
  platform’s library.
  - `microsoft/onnxruntime` GitHub releases returned 404 from here, so
    NuGet is the source.
  - `options(layaR.onnxruntime_url=)` overrides the URL (the tests use
    it).
- **When it runs:**
  - [`laya_download_model()`](https://gueyenono.github.io/layaR/reference/laya_download_model.md)
    installs the runtime if it’s missing.
  - `connect()` calls `ensure_runtime()` before the first engine.
    Interactive sessions get a prompt; others get
    `laya_error_runtime_not_found`.
- **Pins that must move together:**
  - the `ort` crate version (`=2.0.0-rc.13`, `default-features = false`,
    `features = ['load-dynamic']`) in `src/rust/Cargo.toml`;
  - `ort_version`, `ort_min_version`, `ort_nupkg_sha512` and
    `ort_nupkg_size_mb` in `R/runtime.R`;
  - `ORT_VERSION` in `lib.rs`.

  rc.13 with api-27 requires ORT \>= 1.27. Newer ORT versions load fine;
  older ones are refused.
- **One load per process:** ORT loads once per R session and can’t be
  swapped; restart R to change it.
- **ort rc.13 bug:** a failed load permanently breaks later loads in
  that process (uninitialized `OnceLock`). `runtime.rs` therefore checks
  the library itself first (opens, `OrtGetApiBase`, version) and sets
  `POISONED` if `ort` still fails. ort rc.15 fixed this (commit
  0381990), but laya v0.5.1 uses rc.13. If laya moves to rc.15+, the
  pre-check can stay but the comment should be updated.
- **Threads:** with Microsoft’s ORT build, more intra-op threads than
  physical cores is slow. On a 4-core/8-thread i7-4790K (2026-11-22),
  0.2.0 and 0.1.1 (ORT linked in) took the same time at 2 and 4 threads
  and at the default (one per physical core). At 8 threads 0.2.0 was
  about 45% slower (about 900 ms against 600 ms for the triage preset).
  The default never goes past the physical cores. The vignette advises
  against more, and notes that `parallel::detectCores(logical = FALSE)`
  doesn’t count physical cores on Linux.
- **Windows:** `onnxruntime.dll` needs the MSVC runtime
  (`vcruntime140`/`msvcp140`). The `runtime_load` error mentions the
  Visual C++ Redistributable.

## CI (.github/workflows)

- `R-CMD-check.yaml`: runs on push and PR.
  - Matrix: macOS arm64, Windows, and Ubuntu (release, devel, oldrel-1).
  - It downloads and caches ORT and sets `LAYAR_TEST_RUNTIME=true`.
    There’s no model, so the model tests skip (about 17 skips).
  - Windows needs the `x86_64-pc-windows-gnu` Rust target. The `runner`
    context isn’t available in job-level `env`, hence the `GITHUB_ENV`
    step. `actions/cache` rejects paths containing `..`.
- `model-tests.yaml`: manual. It also runs on PRs that change the
  workflow file.
  - Start it with
    `gh workflow run model-tests.yaml --ref <branch> -f os=windows-latest|macos-latest|ubuntu-latest|all -f checkpoint=multilingual|english|typed-decisions|all -f parity=core|all`.
  - Models (0.8–1 GB each) and ORT are cached per OS. GitHub caches are
    branch-scoped: a branch can restore its own caches and those made on
    `main`, nothing else. All six model caches (three checkpoints on
    Windows and macOS) were made on `main` on 2026-11-22, so any branch
    can use them. After bumping a model cache key, run the workflow once
    on `main` (`--ref main`) so the new caches are shared too.
  - The repo’s caches total about 8 GB (2026-11-22), under GitHub’s 10
    GB limit. Over the limit, GitHub evicts the least recently used
    caches. Model caches saved by a feature branch are wasted space once
    the branch is deleted: find them with `gh cache list` and delete
    them with `gh cache delete <id>`.
  - Last runs: 2026-11-22 on `main`, all green on Windows and macOS for
    every checkpoint (core parity); 2026-11-22, typed-decisions with all
    parity cases on both, green.
- `pkgdown.yaml`: builds the site; deploys on `main` and on releases.

## Test coverage gaps

- Bridge, predict, annotate and robustness tests use `multilingual`
  only.
- Windows rejects `laya_import_model(method = "symlink")`: symlink
  detection fails there, so the default there is `"copy"`.

  `vignettes/articles/*.Rmd.orig`), then run
  `Rscript data-raw/knit_vignettes.R [name ...]` after installing the

  - Knit the benchmarks (`models-and-performance`) on an idle machine:
    closing a browser or chat app isn’t enough if it keeps running in

    still matches the numbers after each knit.

    `.Rmd` without knitting again.

- After any dependency change, regenerate `LICENSE.note` with
  `rextendr::write_license_note()`. Then re-add the hand-written tail:
  ORT is not included, and the test fixtures are Apache-2.0 from Convai
  Innovations.

## Releasing (the pattern used for 0.1.1 and 0.2.0)

1.  Merge feature PRs into `main` with merge commits
    (`gh pr merge N --merge`).
2.  Open a branch `release-X.Y.Z` and a PR “Release X.Y.Z”. It only
    changes `Version:` in `DESCRIPTION` and renames the
    `# layaR (development version)` heading in `NEWS.md`. Merge it once
    CI is green.
3.  Publish the release on that merge commit:
    `gh release create vX.Y.Z --target <sha> --title "layaR X.Y.Z" --notes-file <that NEWS section>`.
    r-universe picks it up within about an hour.
4.  Later, a PR “Start development version X.Y.Z.9000” bumps
    `DESCRIPTION` and adds a new `# layaR (development version)`
    heading.

## Conventions

- Commit or push only when asked. Work on a branch and open a PR; don’t
  push to `main`.
- End commit messages with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. End PR
  bodies with
  `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- Errors: use `laya_abort(msg, kind = ...)`. Every failure is a classed
  `laya_error_<kind>`. Document new kinds in `R/conditions.R`, and test
  them with `expect_error(..., class = "laya_error_<kind>")`.
- Options are documented in `R/layaR-package.R`: `layaR.checkpoint`,
  `layaR.threads`, `layaR.model_root`, `layaR.model_repo`,
  `layaR.onnxruntime`, `layaR.shared_cache`.
- Each engine holds about 1–1.6 GB. Tests keep one engine alive at a
  time.
- Add user-visible changes to `NEWS.md` under the development heading.
